# Deploying CYSTEMD

CYSTEMD runs either **inside its Nomad fork** (the `cystemd` agent) or **next
to upstream Nomad** (`cystemd-server`). Both use Consul for state and Vault
through a Vault Agent; neither holds a long-lived Vault token.

```
                ┌──────────────── server hosts (×3) ────────────────┐
  browser ─────▶│ cystemd agent: Nomad server + control plane       │
  cystemd CLI   │   /v1/  Nomad API      /api/  CYSTEMD API         │
                │   /ui/  CYSTEMD web UI (replaces Nomad's)         │
                │ consul agent · vault-agent (AppRole, API proxy)   │
                └───────────────────────┬───────────────────────────┘
                                        │ Nomad RPC
                ┌──────────────── client hosts ─────────────────────┐
                │ cystemd agent: Nomad client + systemd task driver │
                │ consul agent · vault-agent (templates from v4)    │
                │ your services: systemd units CYSTEMD manages      │
                └───────────────────────────────────────────────────┘
```

| File | What it is |
|---|---|
| [`agent/server.hcl`](agent/server.hcl) | Nomad server agent with the control plane enabled |
| [`agent/client.hcl`](agent/client.hcl) | Nomad client agent: the systemd driver and its allowlists, v4 node pools as node meta |
| [`agent/control-plane.hcl`](agent/control-plane.hcl) | Control plane configuration (embedded or `cystemd-server -config`) |
| [`systemd/cystemd.service`](systemd/cystemd.service) | The cystemd agent unit |
| [`systemd/vault-agent.service`](systemd/vault-agent.service) | Vault Agent on a host |
| [`systemd/cystemd-server.service`](systemd/cystemd-server.service) | Standalone control plane (hardened) |
| [`vault-agent/vault-agent.hcl`](vault-agent/vault-agent.hcl) | Host Vault Agent: AppRole, API proxy, a `.env` template (generated by `internal/vaultagent`) |
| [`vault/setup.sh`](vault/setup.sh), [`vault/policies`](vault/policies) | Vault: KV v2, JWT auth for Nomad workload identities, AppRole, roles and policies |
| [`consul/setup.sh`](consul/setup.sh), [`consul/policies`](consul/policies) | Consul ACL policy and token of the control plane |
| [`nomad/acl/cystemd-control-plane.hcl`](nomad/acl/cystemd-control-plane.hcl) | Nomad ACL policy of the control plane |
| [`nomad/cystemd-server.nomad.hcl`](nomad/cystemd-server.nomad.hcl) | The control plane as a Nomad job, with Vault Agent init + sidecar tasks |
| [`nomad/vault-agent.nomad.hcl`](nomad/vault-agent.nomad.hcl) | A Vault Agent on every host, run by Nomad through the systemd driver |

## 1. Consul, Vault, Nomad ACLs

```sh
# Vault: KV, JWT auth trusting Nomad's workload identities, AppRole, policies.
VAULT_ADDR=… VAULT_TOKEN=<admin> NOMAD_ADDR=https://nomad.example.com:4646 deploy/vault/setup.sh

# Consul: the control plane's policy and token.
CONSUL_HTTP_ADDR=… CONSUL_HTTP_TOKEN=<acl admin> deploy/consul/setup.sh

# Nomad: the control plane's policy and token.
nomad acl policy apply -description "CYSTEMD control plane" cystemd-control-plane deploy/nomad/acl/cystemd-control-plane.hcl
nomad acl token create -name cystemd-control-plane -policy cystemd-control-plane

# Keep both tokens in Vault; the Vault Agent renders them to files.
vault kv put secret/cystemd/control-plane nomad_token=… consul_token=…
```

Every step is idempotent. The policies grant only what the control plane uses:
jobs in all namespaces, read access to nodes and node pools, its KV prefix,
the leader-lock session and the Consul keys under `config/`. Widen the
`config/` prefix to match your applications' keys.

## 2a. The cystemd agent (fork)

On every host, install the `cystemd` binary (`make agent`), Consul and Vault
Agent, then:

```sh
install -D deploy/systemd/cystemd.service /etc/systemd/system/cystemd.service
install -D deploy/agent/server.hcl /etc/cystemd/agent.d/server.hcl         # servers
install -D deploy/agent/client.hcl /etc/cystemd/agent.d/client.hcl         # clients
install -D deploy/agent/control-plane.hcl /etc/cystemd/control-plane.hcl   # servers
systemctl enable --now vault-agent cystemd
```

The control plane starts in the server agents. With Consul enabled, all three
serve the API and the UI and one reconciles applications, so it fails over
with Raft. The first start writes the `admin` password to
`/var/lib/cystemd/cystemd/initial-admin-password`.

## 2b. cystemd-server (upstream Nomad)

Run the control plane as a Nomad job:

```sh
nomad job run -var version=v5.0.0 deploy/nomad/cystemd-server.nomad.hcl
```

Or run it as a host service with `deploy/systemd/cystemd-server.service` and a
local Vault Agent. On upstream Nomad, the systemd driver is installed as
an external plugin (`make driver` → `cystemd-driver-systemd` in the client's
`plugin_dir`).

## Vault Agent

| Where | Logs in with | Does |
|---|---|---|
| Server hosts (`vault-agent.service`, AppRole `cystemd-server-host`) | AppRole | API proxy on `127.0.0.1:8100` for the embedded control plane |
| Client hosts (`vault-agent.service`, AppRole `cystemd-host`, or `vault-agent.nomad.hcl`) | AppRole, or the job's workload identity | Templates migrated from CYSTEMD v4 (`VAULT_TEMPLATES`, `.env` files) |
| `cystemd-server` job (`vault-agent-init`, `vault-agent`) | Workload identity, role `cystemd-control-plane` | The control plane's Nomad and Consul tokens; API proxy |
| Applications with `secretsDelivery: vault-agent` | Workload identity, role `cystemd-workloads` | Per-allocation init + sidecar rendering the service's env files |
| Applications with the default delivery | Workload identity (Nomad's template runner) | Same files, rendered by Nomad itself |

`cystemd migrate` turns a CYSTEMD v4 host's `.env` (`VAULT_ADDRESS`,
`VAULT_ROLE_ID`, `VAULT_TEMPLATES`…) into a Vault Agent configuration for that
host (see [docs/MIGRATION.md](../docs/MIGRATION.md)).

## Git webhooks

Applications are compared with Git every `reconcile_interval`; a webhook makes
it immediate. Point your Git server's push webhook at
`https://cystemd.example.com/api/webhook` (on the agent: any server agent's
address) with a secret, and give the control plane the same secret:

```hcl
webhook {
  secret_file = "/etc/cystemd/secrets/webhook-secret"
}
```

GitHub, Gitea, Gogs and Bitbucket sign their requests with it; GitLab sends it
as its token. JSON and form-encoded payloads are both accepted. The response
lists the Applications that were refreshed.

## Upgrading

The agent is upgraded like Nomad: one server at a time (the control plane
fails over to another server), then the clients. A client's units keep
running while its agent restarts; the driver re-attaches to them.
